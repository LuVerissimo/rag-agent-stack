Retrieval-Augmented Generation (RAG)

Retrieval-Augmented Generation (RAG) is a technique that combines information retrieval with large language model generation. Instead of relying solely on the model's training data, RAG systems retrieve relevant documents from an external knowledge base and use them as context when generating a response.

How RAG Works

A RAG pipeline consists of two main phases: indexing and retrieval.

During indexing, documents are loaded from a source, split into smaller chunks, and converted into vector embeddings. These embeddings are stored in a vector database such as Chroma, Pinecone, or pgvector. Each embedding captures the semantic meaning of its corresponding chunk.

During retrieval, a user query is embedded using the same embedding model. The system performs a similarity search against the vector database to find the most relevant chunks. These chunks are then passed as context to the language model, which generates a final answer grounded in the retrieved content.

Why RAG?

RAG addresses several limitations of standard language models. First, language models have a knowledge cutoff and cannot access information that postdates their training. RAG allows the system to query up-to-date documents at inference time.

Second, RAG reduces hallucination. By grounding the model's response in retrieved context, the system is less likely to fabricate information. The model is instructed to answer only from the provided context.

Third, RAG makes the system transparent and auditable. Each answer can be traced back to specific source documents and chunks, enabling citation and verification.

Key Components

Vector Database: Stores chunk embeddings and enables fast similarity search. Common choices include Chroma (local), Pinecone (cloud), and pgvector (Postgres extension).

Embedding Model: Converts text into dense vector representations. Sentence-transformers models such as all-MiniLM-L6-v2 are popular open-source choices that run locally without API calls.

Chunking Strategy: Documents are split into overlapping chunks to preserve context across boundaries. RecursiveCharacterTextSplitter is the standard approach in LangChain, splitting on paragraphs, then lines, then sentences.

Retriever: Given a query embedding, the retriever performs a nearest-neighbor search and returns the top-k most similar chunks. The value of k is configurable and affects both recall and context window usage.

Language Model: The final component that synthesizes the retrieved chunks into a coherent answer. The model is prompted to stay faithful to the provided context and cite sources where possible.

Evaluation

RAG systems are evaluated on two primary metrics. Faithfulness measures whether the generated answer is grounded in the retrieved context and does not introduce information not present in the chunks. Answer relevancy measures whether the answer actually addresses the user's question. Tools like DeepEval and RAGAS provide automated scoring for these metrics.

Common Failure Modes

Chunking too aggressively can split related information across chunks, causing the retriever to miss relevant context. Chunking too loosely can flood the context window with irrelevant information.

Poor embedding model fit can result in semantically relevant chunks being ranked low in retrieval. The embedding model should be chosen to match the domain and language of the documents.

Retrieval with a low k value may miss relevant chunks entirely. Retrieval with a high k value may dilute the context with noise.
